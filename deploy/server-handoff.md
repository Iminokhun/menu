# Меню для кафе на сервере Prosto ERP

**Бэкенд:** свой сервер на **Dart** (shelf). Он собирается в один готовый
исполняемый файл, Dart на сервере не нужен.

**База:** **SQLite**, это один файл `menu.db` внутри папки данных проекта.
**Отдельный контейнер с PostgreSQL или MySQL не нужен.** Значит, нет
контейнера с базой, нет её порта и нет лишних 512 МБ–1 ГБ памяти. Наружу
базе выходить просто некуда: это файл в каталоге проекта, а не сетевой
сервис. Резервные копии уже встроены: каждую ночь копия базы проверяется на
целостность, хранятся последние 14 копий, восстановление делается одной
командой.

**Dockerfile уже есть**, вместе со всем остальным, в папке `deploy/`:

- `Dockerfile`: один образ, в котором API, веб-меню и главная админка.
  Внутри работает не от root, есть healthcheck `/api/health`.
- `docker-compose.yml`: один контейнер `menu`, лимит памяти 512 МБ, **портов
  на сервере не открывает**. Подключён к общей сети `edge` под именем
  `cafe-menu` (сеть внешняя: `docker network create edge`, один раз).
- `nginx-menu.conf`: готовый блок для вашего nginx.
- `backup.sh`: ночная копия через cron. `README.md`: памятка по первому
  запуску, обновлению, откату и восстановлению.
- Caddy в compose выключен и запускаться не будет: HTTPS делает ваш nginx.

## Одно отличие от вашей схемы

Веб-меню отдаёт сам сервер меню, не nginx. Поэтому в nginx нужен не блок с
`root` для файлов и `/api/`, а **один `location /`, который пересылает всё**
на `http://cafe-menu:8090`. По этому адресу:

- `/` — меню для гостей;
- `/menu-kg/` — главная админка;
- `/api/` — API;
- `/uploads/` — фото.

Так в nginx ERP ничего не нужно пересобирать при обновлении меню.

## Итоговая схема

```
Cloudflare → nginx ERP (80/443)
  ├─ prostoerp.com       → Prosto ERP (без изменений)
  └─ menu.prostoerp.com  → cafe-menu:8090 по сети edge (сайт + API + SQLite)
```

## Что нужно в блоке nginx для поддомена

- сертификат `*.prostoerp.com` из вашего конфига;
- `client_max_body_size 30m`: кафе загружают 3D-модели до 25 МБ. Бесплатный
  Cloudflare пропускает до 100 МБ, так что тут проблем нет;
- `proxy_read_timeout` и `proxy_send_timeout 180s`;
- заголовки `Host`, `X-Forwarded-For`, `X-Forwarded-Proto`.

Всё это уже есть в `nginx-menu.conf`, туда нужно только вписать домен и пути
сертификата.

## Сеть edge

nginx ERP работает в контейнере, поэтому `127.0.0.1` из него — это он сам.
Связь через общую сеть Docker:

- сеть создаётся один раз вручную: `docker network create edge` — ничья,
  `docker compose down` ни одного проекта её не удалит;
- проект меню: уже подключён (`deploy/docker-compose.yml`, `external: true`),
  портов наружу нет;
- Prosto ERP: в `docker-compose.prod.yml` у nginx добавить сеть `edge`
  (`external: true`, `name: edge`), в `nginx.conf` — блок из
  `nginx-menu.conf`.

**Важно:** в блоке адрес задан через `resolver 127.0.0.11` и переменную
(`set $cafe_menu …; proxy_pass $cafe_menu;`), а не прямо
`proxy_pass http://cafe-menu:8090`. С прямым адресом nginx ищет `cafe-menu`
при старте и, если контейнер меню в этот момент остановлен, **не запускается
целиком — вместе с ERP**. С переменной в худшем случае только меню отвечает
502, ERP работает.
