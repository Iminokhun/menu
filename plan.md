# План исправлений после проверки

Шесть агентов проверили две последние доработки: QR-коды и 3D-просмотр блюд.
Критичных проблем нет: данные не теряются, одно кафе не может попасть в данные
другого. Ниже то, что нужно исправить до запуска на сервере.

## Сначала: до запуска на сервере

### 1. ✅ Одно испорченное блюдо делает всё меню пустым (сделано)
- **Проблема:** сервер не проверяет, что в блюде пришло (цена, порядок, порции).
  Приложение читает блюда без проверки и при первой ошибке возвращает пустой список.
- **Исправить:**
  - сервер: проверять `price` (число от 0), `sort_order` (целое), `portions`
    (список `{name: текст, price: число}`), иначе ответ 400 с понятным текстом;
  - приложение: читать каждое блюдо отдельно и терпимо к типам
    (`Product.fromJson`, `Portion.fromJson`), пропускать только испорченное блюдо.
- **Файлы:** `server/lib/api.dart`, `lib/database.dart`, `lib/models/product.dart`,
  `lib/models/branch.dart`, `lib/api/api_client.dart`.

### 2. ✅ Нет интернета — гость видит «пусто», а не «ошибка» (сделано)
- **Решение:** меню сохраняется на устройстве и показывается без интернета
  с пометкой «Нет связи — меню от …». Свежее меню берётся при запуске,
  по значку ⟳ «Обновить» и после выхода из админки (`lib/menu_store.dart`).
- **Проблема:** `getAllProducts` и `getBranches` прячут любую ошибку и возвращают пустой список.
  Меню пустое, планшет пишет «Филиалы не найдены», кнопки «Повторить» нет.
  Админка на планшете может открыться на чужом филиале.
- **Исправить:** ошибки сети и сервера передавать дальше. На экранах меню,
  выбора филиала и админки показывать «Нет связи с сервером» и кнопку «Повторить».
- **Файлы:** `lib/database.dart`, `lib/screens/welcome_screen.dart`,
  `lib/screens/menu_screen.dart`, `lib/screens/branch_picker_screen.dart`,
  `lib/screens/admin/admin_shell.dart`.

### 3. ✅ Адрес филиала можно испортить вручную (сделано)
- **Проблема:** поле «Адрес для ссылки» в настройках филиала принимает любой текст
  (`Центр 2`, `a&b`, `a/b`). Сервер такой адрес сохраняет, QR-код получается нерабочим.
- **Исправить:**
  - сервер: в `_createBranch` и `_updateBranch` принимать только `a-z`, `0-9` и `-`,
    иначе ответ 400 «Адрес может содержать только латинские буквы, цифры и дефис»;
  - приложение: при вводе приводить текст к правильному виду (через `_slugify`);
  - в ссылке QR кодировать адрес (`Uri.encodeQueryComponent`).
- **Файлы:** `server/lib/api.dart`, `lib/screens/admin/admin_shop_screen.dart`.

### 4. ✅ Загрузка 3D-модели расходует много памяти сервера (сделано)
- **Сделано также:** фото при загрузке уменьшаются до 1600 px и пережимаются
  (JPEG, прозрачные — PNG), не-фото отклоняются; 3D-модель хранится и
  передаётся сжатой (gzip), если это экономит больше 10% (`server/lib/media.dart`).
- **Проблема:** файл собирается в `List<int>`, это до 200–400 МБ на один файл в 25 МБ.
  Несколько загрузок одновременно могут уронить сервер для всех кафе.
- **Исправить:** собирать файл в `BytesBuilder(copy: false)`. Отказывать сразу,
  если заголовок `content-length` больше лимита.
- **Файл:** `server/lib/api.dart` (`_upload`).

### 5. ✅ «Отмена» во время загрузки приводит к ошибке в приложении (сделано)
- **Проблема:** если нажать «Отмена» в карточке блюда, пока загружается фото
  или модель, после загрузки вызывается `setS` у закрытого окна.
- **Исправить:** пока идёт загрузка, кнопка «Отмена» неактивна.
  Перед каждым `setS` проверять `ctx.mounted`.
- **Файл:** `lib/screens/admin/admin_products_screen.dart`.

### 6. ✅ Печать QR без интернета не работает (сделано)
- **Проблема:** шрифт для PDF скачивается из Google в момент печати.
  Без сети печать падает с непонятной ошибкой.
- **Исправить:** положить шрифт Manrope (обычный и жирный) в приложение (assets)
  и брать его оттуда.
- **Файлы:** `lib/widgets/qr_sticker.dart`, `pubspec.yaml`, `assets/fonts/`.

### 7. ✅ Опечатка в папке тихо отключает сайт (сделано)
- **Проблема:** если `MENU_WEB_DIR` или `SUPER_WEB_DIR` указаны, но папки нет,
  сервер запускается молча, а сайт и `/menu-kg/` отвечают «не найдено».
- **Исправить:** при запуске писать предупреждение и выходить с ошибкой.
- **Файл:** `server/bin/server.dart`.

### 8. ✅ QR-ссылка может получиться неправильной (сделано)
- **Проблема:** без `MENU_URL` и `PUBLIC_URL` сервер угадывает адрес из запроса.
  Ссылка может выйти с `localhost` или внутренним адресом.
- **Исправить:** при запуске без `MENU_URL` писать предупреждение.
  При запуске на сервере обязательно задать `MENU_URL`.
- **Файл:** `server/bin/server.dart`.

### 9. ✅ Сбой одного запроса блокирует создание филиалов (сделано)
- **Проблема:** в разделе «Филиал» при сбое загрузки тарифа лимит остаётся 0,
  и кнопка «Новый филиал» прячется, как будто тариф закончился.
- **Исправить:** при ошибке показывать сообщение и кнопку «Повторить»,
  а не замок лимита.
- **Файл:** `lib/screens/admin/admin_shop_screen.dart` (`_load`).

### 10. ✅ Проверка обновления старой базы (сделано)
- **Проблема:** добавление колонки `model_url` в уже существующую базу
  ни разу не проверялось. Если оно не сработает, сервер не запустится на настоящей базе.
- **Сделать:** тест `server/tool/migrate_test.dart`:
  - создать базу со старой таблицей `products` без `model_url`, добавить блюдо;
  - открыть через `openDb`, проверить, что колонка появилась, а у старого блюда `model_url = ''`;
  - открыть второй раз, ошибки быть не должно.

## Подготовка к запуску на сервере
1. ✅ `/api/health` — сервер жив, база и папка файлов на месте (200 или 503).
2. ✅ Резервные копии: `server backup <папка> [--keep=14]` (можно при работающем
   сервере, `VACUUM INTO` + проверка целостности, файлы докопируются) и
   `server restore <папка>/db/menu-….db` (только при остановленном сервере,
   прежняя база сохраняется рядом). Тест: `dart run tool/backup_test.dart`.
3. ✅ Защита (`server/lib/security.dart`, тест `tool/security_test.dart`): админка
   доступна из браузера только со своих сайтов (MENU_URL, PUBLIC_URL,
   CORS_ORIGINS), меню и фото — всем; защитные заголовки (HSTS — в Caddy);
   не больше 60 загрузок за 10 минут и 2 ГБ места на кафе (UPLOAD_QUOTA_MB).
4. ✅ `deploy/`: Dockerfile (сервер + сайт меню + главная админка, Flutter 3.47.6
   из официального репозитория, без root), docker-compose.yml (menu + Caddy,
   данные на диске сервера, ротация логов), Caddyfile (HTTPS, HSTS, сжатие,
   лимит 30 МБ), .env.example, backup.sh (для cron). Сайт меню обращается к
   API по своему адресу — образ не зависит от домена. Docker локально не
   проверялся (нет Docker) — проверка при первом запуске на сервере.
5. ✅ Памятка `deploy/README.md`: первый запуск, обновление, откат, восстановление, проверка. Заодно исправлен импорт из Supabase: кафе получает пробный срок (раньше меню выключилось бы сразу) и папка данных создаётся сама.

## Как проверить
- `dart analyze` в `server/` и `flutter analyze` в корне: без новых замечаний.
- `dart run tool/migrate_test.dart`: проходит.
- `dart run tool/smoke_test.dart <логин> <пароль>` (тестового главного админа): все проверки проходят.
- Вручную в Chrome:
  - выключить сервер: меню показывает «Нет связи» и «Повторить»;
  - ввести адрес филиала `Центр 2`: появляется понятная ошибка;
  - нажать «Отмена» во время загрузки модели: ошибки нет;
  - напечатать QR без интернета: PDF получается.
